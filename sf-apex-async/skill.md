# SF Apex Async

Creates production-grade asynchronous Apex classes with proper error handling, chaining patterns, and comprehensive test coverage. **Works with any Salesforce project** regardless of naming conventions or structure.

## When to Use

- Creating Queueable classes (with Finalizer for error handling)
- Creating Batch classes (start/execute/finish pattern)
- Creating Schedulable classes (scheduled jobs)
- Implementing async processing with chaining
- Background job creation
- Large dataset processing
- Scheduled data operations

## Instructions

### Step 1: Detect Project Prefix

Use `sf-prefix-detect` skill to determine the project prefix.

**Quick fallback (if skill unavailable):**
1. Get working directory name
2. Apply transformation:
   - `Crm[Name]` → `[NAME]_`
   - `[Name]` → `[NAME]_`
3. Validate: 2-10 uppercase characters + underscore

### Step 2: Determine Async Type

Ask user which async pattern is needed (or infer from request):

**Option 1: Queueable**
- For async processing with chaining capability
- Accepts complex objects (not just primitives)
- Can chain to other Queueables
- Supports callouts
- Job tracking with `AsyncApexJob`
- Max 50 jobs per transaction
- Best for: Post-processing, callouts, moderate data volumes

**Option 2: Batch**
- For large dataset processing (up to 50M records)
- Chunked processing with configurable batch size
- Automatic governor limit reset per batch
- Three-phase pattern: start → execute → finish
- Best for: Mass updates, data cleanup, scheduled processing

**Option 3: Schedulable**
- For scheduled recurring jobs
- Typically delegates to Batch or Queueable
- Cron expression for scheduling
- Best for: Daily/weekly/monthly operations

### Step 3: Gather Requirements

Ask user for (or infer from request):

**Required:**
- **Class name** (without prefix — will be added automatically)
- **Description**: What does this async job do?
- **Processing scope**: What data/records to process?

**Optional (smart defaults):**
- Target object (for Batch queries)
- Batch size (for Batch - default: 200)
- Chain depth limit (for Queueable - default: 5)
- Callout needed (for Queueable - adds `Database.AllowsCallouts`)
- Schedule expression (for Schedulable)

**Auto-detected:**
- Current date: `[Month, Year]` (e.g., "May, 2026")
- ISO date: `[YYYY-MM-DD]` for attribution
- API version: Read from `sfdx-project.json` or default to `66.0`

```apex
/**
 * Batch job for [description].
 * Processes records in chunks to handle large data volumes.
 */
public with sharing class [PREFIX]_[Name]Batch implements Database.Batchable<SObject>[, Database.Stateful] {

    private String query;
    private Integer successCount = 0;
    private Integer errorCount = 0;

    /**
     * Constructor with default query
     */
    public [PREFIX]_[Name]Batch() {
        this.query = 'SELECT Id, Name FROM [Object] WHERE [Condition] WITH USER_MODE';
    }

    /**
     * Constructor with custom query
     * @param query SOQL query to execute
     */
    public [PREFIX]_[Name]Batch(String query) {
        this.query = query;
    }

    /**
     * Start method - define scope of records to process
     * @param bc Batchable context
     * @return QueryLocator for records to process
     */
    public Database.QueryLocator start(Database.BatchableContext bc) {
        System.debug('Batch job starting with query: ' + query);
        return Database.getQueryLocator(query);
    }

    /**
     * Execute method - process each batch of records
     * @param bc Batchable context
     * @param scope List of records in this batch
     */
    public void execute(Database.BatchableContext bc, List<SObject> scope) {
        System.debug('Processing batch of ' + scope.size() + ' records');

        // Process records
        List<SObject> recordsToUpdate = new List<SObject>();
        
        for (SObject record : scope) {
            try {
                // TODO: Apply business logic
                // Example: record.put('Status__c', 'Processed');
                recordsToUpdate.add(record);
                
            } catch (Exception e) {
                System.debug(LoggingLevel.ERROR, 'Error processing record ' + record.Id + ': ' + e.getMessage());
                errorCount++;
            }
        }

        // Perform DML with partial success (allows batch to continue on errors)
        if (!recordsToUpdate.isEmpty()) {
            Database.SaveResult[] results = Database.update(recordsToUpdate, false, AccessLevel.USER_MODE);
            
            // Handle DML errors
            for (Integer i = 0; i < results.size(); i++) {
                if (results[i].isSuccess()) {
                    successCount++;
                } else {
                    errorCount++;
                    Database.Error error = results[i].getErrors()[0];
                    System.debug(LoggingLevel.ERROR, 
                        'Error updating record ' + recordsToUpdate[i].Id + 
                        ': ' + error.getMessage() + 
                        ' (Code: ' + error.getStatusCode() + ')');
                }
            }
        }
    }

    /**
     * Finish method - cleanup, notifications, and statistics
     * @param bc Batchable context
     */
    public void finish(Database.BatchableContext bc) {
        // Query job info
        AsyncApexJob job = [
            SELECT Id, Status, NumberOfErrors, JobItemsProcessed, 
                   TotalJobItems, CreatedDate, CompletedDate
            FROM AsyncApexJob
            WHERE Id = :bc.getJobId()
            LIMIT 1
        ];

        // Log statistics
        System.debug('Batch job completed');
        System.debug('Status: ' + job.Status);
        System.debug('Total batches: ' + job.TotalJobItems);
        System.debug('Batches processed: ' + job.JobItemsProcessed);
        System.debug('Success count: ' + successCount);
        System.debug('Error count: ' + errorCount);
        
        // TODO: Send completion notification
        // - Email to admin
        // - Create custom log record
        // - Update status field
        // - Chain to next job if needed
    }
}
```

## Async Patterns & Best Practices

### Queueable Best Practices

**Chain Depth Limiting:**
```apex
private static final Integer MAX_CHAIN_DEPTH = 5;

public void execute(QueueableContext context) {
    if (chainDepth >= MAX_CHAIN_DEPTH) {
        System.debug('Max chain depth reached');
        return;
    }
    
    // Process records...
    
    // Chain to next job
    if (hasMoreWork()) {
        System.enqueueJob(new MyQueueable(nextBatch, chainDepth + 1));
    }
}
```

**Finalizer Pattern:**
```apex
public void execute(QueueableContext context) {
    try {
        // Process records
        
        // Attach Finalizer for cleanup
        System.attachFinalizer(new MyFinalizer(context.getJobId()));
        
    } catch (Exception e) {
        // Finalizer can handle errors
        System.attachFinalizer(new MyFinalizer(context.getJobId(), e));
    }
}

private class MyFinalizer implements System.Finalizer {
    public void execute(System.FinalizerContext context) {
        // Always executes, even on error
        // Perfect for cleanup, logging, notifications
    }
}
```

**Job Tracking:**
```apex
// Query job status
AsyncApexJob job = [
    SELECT Id, Status, NumberOfErrors, ExtendedStatus
    FROM AsyncApexJob
    WHERE Id = :context.getJobId()
];
```

### Batch Best Practices

### Schedulable Best Practices

**Common Cron Expressions:**
```apex
// Daily at 2 AM
'0 0 2 * * ?'

// Every Monday at 9 AM
'0 0 9 ? * MON'

// First day of month at midnight
'0 0 0 1 * ?'

// Every 15 minutes
'0 0/15 * * * ?'

'0 0 8 ? * MON-FRI'

// Last day of month at 11 PM
'0 0 23 L * ?'
```

**Cron Format:**
```
Seconds Minutes Hours Day_of_month Month Day_of_week Optional_year
0       0       2     *            *     ?

- Seconds: 0-59
- Minutes: 0-59
- Hours: 0-23
- Day of month: 1-31 (or L for last)
- Month: 1-12 or JAN-DEC
- Day of week: 1-7 or SUN-SAT (? means no specific value)
```

### Governor Limits

**Queueable Limits:**
- Max 50 Queueables per transaction
- Max 1 enqueue per execute (chaining allowed)
- Max chain depth: No hard limit, but use reasonable depth (5-10)
- Shares governor limits with synchronous code

**Batch Limits:**
- Max 5 concurrent batch jobs per org
- Max 100 batch jobs queued or in progress
- Each batch gets fresh governor limits
- Max 50M records can be processed

**Schedulable Limits:**
- Max 100 scheduled jobs per org
- Schedulable itself is lightweight
- Actual limits depend on delegated job (Batch/Queueable)

## Troubleshooting

### Issue: "Too many queueable jobs added to the queue"

**Cause:** Exceeded 50 Queueables per transaction

**Solution:**
1. Use Batch instead for large volumes
2. Process records in larger chunks per Queueable
3. Add chain depth limiting
4. Consider using Batch for initial processing, Queueable for cleanup

### Issue: "Maximum stack depth reached"

**Cause:** Infinite chaining loop

**Solution:**
```apex
private static final Integer MAX_CHAIN_DEPTH = 5;

if (chainDepth >= MAX_CHAIN_DEPTH) {
    System.debug('Max depth reached, stopping chain');
    return;
}
```

### Issue: Batch job running too slowly

**Cause:** Batch size too small or complex processing

**Solution:**
1. Increase batch size: `Database.executeBatch(batch, 500)`
2. Optimize SOQL queries in execute()
3. Remove unnecessary SOQL/DML operations
4. Use Database.Stateful sparingly (adds overhead)

### Issue: "Invalid cron expression"

**Cause:** Incorrect cron syntax

**Solution:**
```apex
// Valid cron expressions:
'0 0 2 * * ?'      // Daily at 2 AM
'0 0 9 ? * MON'    // Every Monday at 9 AM
'0 0 0 1 * ?'      // First day of month

// Invalid:
'0 0 2 * *'        // Missing day_of_week
'0 0 25 * * ?'     // Hour 25 doesn't exist
```

### Issue: Test not completing

**Cause:** Missing Test.stopTest()

**Solution:**
```apex
Test.startTest();
System.enqueueJob(new MyQueueable(recordIds));
Test.stopTest(); // REQUIRED - forces async completion
```

### Issue: Finalizer not executing in tests

**Cause:** Finalizers may not execute in all test scenarios

**Solution:**
- Test Finalizer logic separately
- Test main execution path independently
- Document Finalizer behavior expectations

### Issue: Job fails silently

**Cause:** No error logging or notification

**Solution:**
```apex
public void finish(Database.BatchableContext bc) {

    if (job.NumberOfErrors > 0) {

        // Create error log

    }
}
```

## Async Decision Matrix

| Scenario | Use | Why |
|----------|-----|-----|
| Standard async processing | Queueable | Chainable, accepts objects, job tracking |
| Large datasets (>10k records) | Batch | Chunked processing, governor limit resets |
| Recurring schedule | Schedulable → Batch | Cron-based scheduling |
| Callouts | Queueable + AllowsCallouts | Direct callout support |
| Post-job cleanup | Finalizer | Executes regardless of success/failure |
| Mass updates | Batch | Handles up to 50M records |
| Complex chaining | Queueable | Easier chaining than Batch |
| Stateful counters | Batch + Stateful | Maintain state across batches |
| Immediate async | Queueable | Faster than Batch |

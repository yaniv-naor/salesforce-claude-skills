# SF LWC Create

A Claude Code skill for creating Lightning Web Components with complete structure, including HTML, JavaScript, CSS, metadata, Jest tests, and optional Apex controllers.

## Overview

The **sf-lwc-create** skill automates the creation of production-ready Lightning Web Components following Salesforce best practices and the Claude Code development standards. It generates all necessary files with proper naming conventions, security patterns, and test coverage.

## Features

- **Complete LWC Structure**: Generates HTML, JS, CSS, metadata, and Jest tests
- **Optional Apex Integration**: Creates Apex controllers with test classes when needed
- **Automatic Naming**: Follows LWC naming conventions (lowercase prefix, PascalCase classes, kebab-case tags)
- **Security First**: Uses WITH USER_MODE and proper error handling in all Apex code
- **SLDS Patterns**: Implements Lightning Design System best practices
- **Wire Service**: Supports @wire decorator for reactive data
- **Lightning Components**: Includes lightning-datatable, lightning-card, and other standard components
- **Error Handling**: Comprehensive error handling with toast notifications
- **Test Coverage**: Generates Jest tests and Apex test classes with multiple scenarios
- **Attribution**: All files include generation timestamp for audit trail

## How It Works

### Step 1: Prefix Detection
Uses `sf-prefix-detect` skill to determine project prefix (e.g., ENF_, ABC_, DEF_)

### Step 2: Component Planning
Gathers information about:
- Component name (camelCase)
- Purpose and functionality
- Whether Apex controller is needed
- Target page types (App, Record, Home)
- Supported objects (for Record Pages)

### Step 3: File Generation
Creates complete component structure:
```
force-app/main/default/
├── lwc/[prefix]_[componentName]/
│   ├── [prefix]_[componentName].html
│   ├── [prefix]_[componentName].js
│   ├── [prefix]_[componentName].css
│   ├── [prefix]_[componentName].js-meta.xml
│   └── __tests__/[prefix]_[componentName].test.js
└── classes/ (if Apex needed)
    ├── [PREFIX]_[ComponentName]Ctrl.cls
    ├── [PREFIX]_[ComponentName]Ctrl.cls-meta.xml
    ├── [PREFIX]_[ComponentName]Ctrl_Test.cls
    └── [PREFIX]_[ComponentName]Ctrl_Test.cls-meta.xml
```

### Step 4: Attribution & Summary
Adds "Generated by Claude Code" attribution and provides deployment instructions

## Naming Conventions

| Element | Format | Example |
|---------|--------|---------|
| LWC Folder | `[prefix]_[camelCase]` | `enf_documentViewer` |
| JavaScript Class | `[PrefixPascalCase]` | `EnfDocumentViewer` |
| Apex Class | `[PREFIX]_[PascalCase]Ctrl` | `ENF_DocumentViewerCtrl` |
| HTML Tag | `<c-[prefix]-[kebab-case]>` | `<c-enf-document-viewer>` |

**Note:** LWC uses lowercase prefix (enf_) while Apex uses uppercase (ENF_)

## Component Patterns

### Simple Display Component
- No Apex backend
- Uses @api properties
- Static or record-based display
- Example: Hello World, Record Summary

### Component with Apex (Wire Service)
- @wire decorator for reactive data
- Cacheable Apex methods
- Automatic refresh on property changes
- Example: Document Viewer, Record Details

### Data Table Component
- lightning-datatable element
- Column definitions with types
- List data from Apex
- Example: Account List, Related Records

### Form Component
- lightning-record-edit-form
- Field-level validation
- Success/error handling
- Example: Custom forms, multi-step wizards

## Best Practices Implemented

### Performance
- Cacheable Apex methods for read operations
- LIMIT clauses in SOQL queries
- Lazy loading in connectedCallback
- Minimal DOM updates

### Security
- `WITH USER_MODE` in all SOQL queries
- `with sharing` on all Apex classes
- Input validation in Apex methods
- AuraHandledException for proper error handling

### User Experience
- Loading spinners during data fetch
- Error messages with SLDS styling
- Toast notifications for user feedback
- Responsive design with media queries

### Testing
- Jest tests with describe/it structure
- DOM cleanup in afterEach
- Apex tests with @testSetup
- Multiple test scenarios (success, error, edge cases)

```bash

sf project deploy start -d force-app/main/default/lwc/[component]

# Deploy Apex (if created)
sf project deploy start -d force-app/main/default/classes

# Run Jest tests
npm test

# Run Apex tests
sf apex run test --tests [PREFIX]_[ComponentName]Ctrl_Test
```

## Troubleshooting

### Component Not Visible in App Builder
- Check isExposed is true in metadata
- Verify correct target page types
- Deploy component first
- Refresh App Builder

### Apex Method Not Found
- Verify import path matches class name
- Check @AuraEnabled annotation
- Deploy Apex class before LWC
- Use correct prefix (uppercase for Apex)

### Jest Tests Failing
- Check mock data structure
- Verify DOM cleanup in afterEach
- Use await Promise.resolve() for async
- Mock Apex methods properly

### Wire Not Updating
- Ensure reactive property: `{ recordId: '$recordId' }`
- Verify method is cacheable=true
- Check field-level security
- Use refreshApex() to manually refresh

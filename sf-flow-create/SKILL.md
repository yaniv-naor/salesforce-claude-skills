# SF Flow Create

Creates Salesforce Flow metadata (`.flow-meta.xml`) with proper configuration for all flow types. **Works with any Salesforce project.**

## When to Use

- Creating Record-Triggered Flows (replaces Process Builder)
- Building Screen Flows for guided user experiences
- Setting up Scheduled Flows for recurring automation
- Creating Autolaunched Flows (invocable from Apex/other flows)
- Migrating from Workflow Rules or Process Builder

## Instructions

### Step 1: Detect Project Prefix

Use `sf-prefix-detect` skill to determine the project prefix.

**Flow naming:**
- Flow API Name: `[PREFIX]_[FlowName]`
- File name: `[PREFIX]_[FlowName].flow-meta.xml`
- Example: `ENF_DocumentAfterInsert`, `ENF_CreateInvoiceLineItems`

### Step 2: Gather Flow Information

Ask user for (or infer from request):

**Required:**
- **Flow name** (without prefix, PascalCase) - e.g., `CreateInvoice`, `DocumentValidation`
- **Flow type** - See flow types table below
- **Purpose** - What does this flow do?

**For Record-Triggered Flows:**
- **Trigger object** - Which object triggers this flow?
- **Trigger timing** - Before save, After save
- **Trigger event** - Created, Updated, Deleted
- **Entry conditions** - When should flow run?

**For Screen Flows:**
- **Where launched** - Lightning page, quick action, utility bar
- **Input/output variables** - What data flows in/out

**For Scheduled Flows:**
- **Frequency** - Daily, weekly, custom
- **Query** - Which records to process

**Auto-detected:**
- API Version: Read from `sfdx-project.json` or default to `66.0`
- Status: `Active` or `Draft`

### Step 3: Determine Flow Type

Choose appropriate flow type:

| Flow Type | Use For | Key Features |
|-----------|---------|--------------|
| **Record-Triggered** | Automation when records change | Before/after save, create/update/delete |
| **Screen Flow** | Guided user processes | User input, multi-step wizards |
| **Scheduled Flow** | Recurring automation | Daily/weekly batch processing |
| **Autolaunched** | Called by Apex or other flows | No UI, reusable logic |
| **Platform Event** | Event-driven automation | Subscribe to platform events |

### Step 7: Validation Checks

**CRITICAL: Perform these validations before saving:**

1. **Flow Type Validation:**
   - Screen Flow: `processType` must be `Flow`
   - Record-Triggered: `processType` must be `AutoLaunchedFlow` with `start` element containing trigger configuration
   - Autolaunched: `processType` must be `AutoLaunchedFlow` with basic `start` element
   - Scheduled: Must have `schedule` element in `start`

2. **DML in Loops Detection:**
   - If flow XML contains loops, check that no DML operations (Create Records, Update Records, Delete Records) are inside loop elements
   - Warn user if DML detected in loops
   - Suggest collection pattern: Loop → Add to Collection → DML outside loop

3. **XML Structure Validation:**
   - Valid XML syntax
   - Required elements present (`apiVersion`, `label`, `processType`, `start`, `status`)
   - Proper namespace: `http://soap.sforce.com/2006/04/metadata`

4. **Trigger Configuration Validation (Record-Triggered only):**
   - Must have `object` element
   - Must have `recordTriggerType` (Create, Update, Delete)
   - Must have `triggerType` (RecordBeforeSave, RecordAfterSave)
   - Entry conditions properly formatted if present

## Flow Best Practices

### Bulkification

**Always design for bulk:**
- ✅ Get Records element retrieves multiple records
- ✅ Loop through collection variables
- ✅ Collect records to create/update, then DML once
- ❌ Never put Create/Update Records inside a Loop

**Bad example (NOT bulkified):**
```
Loop through records
  └─ Create Record (executes for each record) ❌
```

**Good example (bulkified):**
```
Loop through records
  └─ Add to collection variable
Create Records (once, with collection) ✅
```

### Error Handling

**Always add fault paths:**
- Every Create/Update/Delete Records element should have fault connector
- Display error messages to users (Screen Flows)
- Log errors for debugging (Record-Triggered)

### Performance

**Optimize query performance:**
- Use specific filter conditions (avoid Get All Records)
- Limit record retrieval when possible
- Index frequently queried fields

**Avoid governor limits:**
- Maximum 2,000 records per flow interview
- Maximum 100 SOQL queries per flow
- Maximum 150 DML operations per flow

### Security

**Respect field-level security:**
- Use "Respect field-level security" checkbox in Get Records
- Check user permissions before DML operations
- Don't expose sensitive data in Screen Flows

## Flow Types Deep Dive

### Record-Triggered Flows

**When to use:**
- Replace Process Builder
- Replace Workflow Rules
- Automate when records change

**Trigger Timing:**

| Timing | Use For | Available Actions |
|--------|---------|------------------|
| **Before Save** | Validate, update fields on same record | Update triggering record fields |
| **After Save** | Create/update other records, send emails | All actions (Create, Update, Delete, Email, etc.) |

**Trigger Events:**
- **Create** - New record inserted
- **Update** - Existing record modified
- **Delete** - Record deleted

**Entry Conditions:**
- Filter which records trigger the flow
- Use formulas for complex logic
- Example: `Status__c = 'Closed' AND Amount__c > 10000`

### Screen Flows

**When to use:**
- Guided user experiences
- Multi-step processes
- Data collection forms

**Key elements:**
- **Screen** - Display information, collect input
- **Decision** - Branch logic based on user input
- **Record Create/Update** - Save data
- **Finish** - Complete flow, return to page

**Launching Screen Flows:**
- Quick Action on object
- Lightning Page component
- Utility bar
- Custom button/link

### Scheduled Flows

**When to use:**
- Daily/weekly batch processing
- Recurring data cleanup
- Scheduled notifications

**Configuration:**
- Frequency: Daily, Weekly, or custom
- Start Date and Time
- Query: Which records to process

**Limits:**
- Maximum 250,000 records per day
- Runs in batches of 200 records
- Use carefully to avoid governor limits

### Autolaunched Flows

**When to use:**
- Reusable logic called from Apex
- Subflows called from other flows
- Platform Event triggered automation

**Invocation methods:**
- `Flow.Interview.createInterview()` in Apex
- Subflow element in other flows
- Platform Event trigger

## Critical Rules & Constraints

### Naming Conventions

| Element | Pattern | Example |
|---------|---------|---------|
| Flow API Name | `[PREFIX]_[Name]` | `ENF_DocumentValidation` |
| Flow Label | `[PREFIX] [Human Name]` | `ENF Document Validation` |
| Variables | camelCase | `accountRecords`, `totalAmount` |
| Resources | PascalCase | `GetAccountRecords`, `UpdateStatus` |

### DML Limits

**Record-Triggered Flows:**
- 1 flow per object per trigger event
- Use `$Record` for triggering record
- Avoid updating same record after save (causes recursion)

**Bulk Limits:**
- Maximum 2,000 records per flow interview
- Design for 200 records minimum

### Formula Syntax

**Use Salesforce formula syntax:**
- `{!Variable}` - Reference variable
- `TEXT()` - Convert to text
- `ISBLANK()` - Check for null
- `IF()` - Conditional logic

### Status Management

**Draft vs Active:**
- **Draft** - Under development, not running
- **Active** - Running in production
- Only 1 version can be active at a time

## Troubleshooting

### Error: Flow not triggering

**Cause:** Inactive flow or entry conditions not met

**Solution:**
1. Check flow status (must be Active)
2. Verify entry conditions logic
3. Test with Debug mode in Flow Builder
4. Check trigger timing (before/after save)

### Error: DML exception in flow

**Cause:** Required fields missing or validation rule failure

**Solution:**
1. Add fault path to DML elements
2. Log error details
3. Check required fields are populated
4. Verify validation rules pass

### Error: Too many SOQL queries

**Cause:** Get Records inside loop

**Solution:**
1. Move Get Records outside loop
2. Use single query with filters
3. Store results in collection variable
4. Loop through collection instead

### Error: Record lock exception

**Cause:** Multiple flows updating same record simultaneously

**Solution:**
1. Consolidate flows (one per object per event)
2. Use Before Save timing when possible
3. Add retry logic for after-save updates
4. Consider using Queueable Apex for complex scenarios

### Error: Variable not found

**Cause:** Variable not defined or wrong API name

**Solution:**
1. Check variable spelling and case
2. Verify variable exists in flow
3. Use correct syntax: `{!VariableName}`
4. Check variable availability (scope)

## Reference

### Flow Element Types

| Element | Purpose | Common Use |
|---------|---------|------------|
| **Assignment** | Set variable values | Store calculations, set flags |
| **Decision** | Branch logic | IF/THEN logic, routing |
| **Loop** | Iterate collection | Process multiple records |
| **Get Records** | Query database | Retrieve related records |
| **Create Records** | Insert records | Create child records |
| **Update Records** | Modify records | Update status, fields |
| **Delete Records** | Remove records | Cleanup, cascade deletes |
| **Screen** | User interface | Collect input, display info |
| **Subflow** | Call another flow | Reusable logic |
| **Action** | Call invocable method | Apex action, send email |

### Trigger Type Matrix

| Object State | Before Save | After Save |
|--------------|-------------|------------|
| **Create** | Validate, set defaults | Create related, send notifications |
| **Update** | Validate changes, update fields | Update related, trigger workflows |
| **Delete** | Prevent deletion | Cleanup related records |

| Frequency | Cron Expression | Use Case |
|-----------|----------------|----------|
| Daily | `0 0 2 * * ?` | Daily cleanup at 2 AM |
| Weekly | `0 0 2 ? * SUN` | Weekly reports on Sunday |
| Monthly | `0 0 2 1 * ?` | Monthly processing on 1st |

# SF Object Create

Creates Salesforce Custom Object metadata (`.object-meta.xml`) with proper configuration, sharing models, and validation. **Works with any Salesforce project.**

## When to Use

- Creating new custom objects
- Generating object metadata XML
- Configuring object sharing and security
- Setting up object features (Activities, History, Reports, Search)
- Creating junction objects for many-to-many relationships
- Troubleshooting object deployment errors

## Instructions

### Step 1: Detect Project Prefix

Use `sf-prefix-detect` skill to determine the project prefix.

**Object naming:**
- Custom objects: `[PREFIX]_[ObjectName]__c`
- Example: `PROJ_Invoice__c`, `ABC_Document__c`

### Step 2: Gather Object Information

Ask user for (or infer from request):

**Required:**
- **Object name** (without prefix/suffix, PascalCase) - e.g., `Invoice`, `Document`, `CustomRecord`
- **Purpose** - What does this object track or manage?
- **Name field type** - Text (for human-named records) or AutoNumber (for transactions/logs)

**Optional:**
- **Plural label** (auto-generated from singular if not provided)
- **Description** (auto-generated from purpose if not provided)
- **Features needed:**
  - Activities (Tasks, Events)
  - History tracking
  - Reports
  - Search
- **Is this a junction object?** (many-to-many relationship)
- **Master-Detail relationships** (if any)

**Auto-detected:**
- API Name: `[PREFIX]_[ObjectName]__c`
- File name: `[PREFIX]_[ObjectName]__c.object-meta.xml`
- Sharing model (based on Master-Detail relationships)

### Step 3: Determine Object Configuration

**A. Name Field Type**

Choose based on object purpose:

| Type | Use For | Requirements |
|------|---------|--------------|
| **Text** | Human-named entities (Projects, Contacts, Locations) | Just label |
| **AutoNumber** | Transactions, logs, tickets, invoices | Display format + starting number |

**Text example:** "Project Name", "Team Name"
**AutoNumber example:** "Invoice Number", "Ticket Number", "Request ID"

**B. Sharing Model**

Critical decision based on relationships:

| Condition | Sharing Model | Why |
|-----------|---------------|-----|
| NO Master-Detail fields | `ReadWrite` | Default org-wide access |
| HAS Master-Detail field(s) | `ControlledByParent` | Required by Salesforce |

**⚠️ CRITICAL:** Using `ReadWrite` with Master-Detail field = deployment error!

**C. Feature Enablement**

Based on object purpose:

**User-Facing Objects** (Apps, Trackers, Business Records):
- Enable: Search, Reports, Activities, History
- Examples: Invoices, Projects, Cases

**System-Facing Objects** (Junctions, Logs, Technical):
- Enable: None (keep lean)
- Examples: Junction objects, system logs, audit records

### Step 4: Generate Object Metadata XML

Create `.object-meta.xml` file with proper structure:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<CustomObject xmlns="http://soap.sforce.com/2006/04/metadata">
    <!-- Generated by Claude Code on [YYYY-MM-DD] -->
    
    <!-- Basic Configuration -->
    <label>[Singular Label]</label>
    <pluralLabel>[Plural Label]</pluralLabel>
    <description>[Description] - Generated by Claude Code</description>
    
    <!-- Name Field -->
    <nameField>
        <label>[Field Label]</label>
        <type>[Text|AutoNumber]</type>
        <!-- If AutoNumber: -->
        <displayFormat>[Format]</displayFormat>
        <startingNumber>1</startingNumber>
    </nameField>
    
    <!-- Sharing & Security -->
    <sharingModel>[ReadWrite|ControlledByParent]</sharingModel>
    <deploymentStatus>Deployed</deploymentStatus>
    <visibility>Public</visibility>
    
    <!-- Features (only if enabled) -->
    <enableActivities>true</enableActivities>
    <enableBulkApi>true</enableBulkApi>
    <enableReports>true</enableReports>
    <enableSearch>true</enableSearch>
    <enableSharing>true</enableSharing>
    <enableStreamingApi>true</enableStreamingApi>
    <enableHistory>true</enableHistory>
</CustomObject>
```

**Key principles:**
- ✅ NO `<fullName>` tag in XML (API name comes from filename)
- ✅ All required fields present
- ✅ Sharing model matches relationships
- ✅ Only include feature tags when enabling (not for `false`)
- ✅ Include attribution in description

### Step 6: Add Validation Rules (Optional)

If user requests validation rules, add them to the object XML:

```xml
<validationRules>
    <fullName>Require_End_Date_After_Start</fullName>
    <active>true</active>
    <description>End date must be after start date</description>
    <errorConditionFormula>End_Date__c &lt; Start_Date__c</errorConditionFormula>
    <errorMessage>End Date must be after Start Date</errorMessage>
</validationRules>
```

**⚠️ CRITICAL:** Validation rule names:
- ✅ NO `__c` suffix (unlike fields)
- ✅ Alphanumeric + underscores only
- ✅ Must begin with letter
- ✅ Cannot end with underscore
- ✅ No consecutive underscores

**Common validation patterns:**

**Required Field:**
```xml
<validationRules>
    <fullName>Require_Status</fullName>
    <active>true</active>
    <errorConditionFormula>ISBLANK(TEXT(Status__c))</errorConditionFormula>
    <errorMessage>Status is required</errorMessage>
</validationRules>
```

**Date Range:**
```xml
<validationRules>
    <fullName>Valid_Date_Range</fullName>
    <active>true</active>
    <errorConditionFormula>
        AND(
            NOT(ISBLANK(Start_Date__c)),
            NOT(ISBLANK(End_Date__c)),
            End_Date__c &lt; Start_Date__c
        )
    </errorConditionFormula>
    <errorMessage>End Date must be after Start Date</errorMessage>
</validationRules>
```

**Conditional Required:**
```xml
<validationRules>
    <fullName>Require_Reason_When_Rejected</fullName>
    <active>true</active>
    <errorConditionFormula>
        AND(
            TEXT(Status__c) = "Rejected",
            ISBLANK(Rejection_Reason__c)
        )
    </errorConditionFormula>
    <errorMessage>Rejection Reason is required when Status is Rejected</errorMessage>
</validationRules>
```

## Critical Rules & Constraints

### Sharing Model Rules

**MUST ENFORCE:**

| Condition | Required Sharing Model | Why |
|-----------|----------------------|-----|
| No Master-Detail fields | `ReadWrite` | Standard org-wide access |
| Has Master-Detail field(s) | `ControlledByParent` | Salesforce requirement |

**❌ Common Error:**
```
Cannot set sharingModel to ReadWrite on a CustomObject with a MasterDetail relationship field
```

**✅ Solution:** Use `ControlledByParent` for any object with Master-Detail relationship(s).

### Master-Detail Constraints

**Limits:**
- Maximum **2** Master-Detail relationships per object
- 3rd relationship must be Lookup

**Junction Objects:**
- Require exactly 2 Master-Detail relationships
- Use `ControlledByParent` sharing model
- Primary Master-Detail = first created (defines ownership)

### Reserved Words (NEVER USE)

| Category | Reserved Words |
|----------|----------------|
| SOQL/SQL | `Select`, `From`, `Where`, `Limit`, `Order`, `Group`, `Having`, `And`, `Or` |
| System | `User`, `External`, `View`, `Type`, `Object`, `Record` |
| Temporal | `Date`, `Time`, `DateTime`, `Number` |

**Example of BAD names:**
- ❌ `Order__c` (reserved word)
- ❌ `User__c` (reserved word)
- ❌ `Select__c` (reserved word)

**Example of GOOD names:**
- ✅ `PROJ_Order__c` (prefix differentiates from reserved word)
- ✅ `PROJ_Customer__c`
- ✅ `PROJ_Request__c`

### XML Structure Rules

**❌ DO NOT include `<fullName>` in XML:**
```xml
<CustomObject xmlns="http://soap.sforce.com/2006/04/metadata">
    <fullName>PROJ_Invoice__c</fullName>  <!-- WRONG! Remove this -->
    <label>Invoice</label>
</CustomObject>
```

**✅ CORRECT (API name from filename):**
```xml
<CustomObject xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>Invoice</label>
    <!-- API name: PROJ_Invoice__c comes from filename -->
</CustomObject>
```

### Naming Conventions

| Element | Pattern | Example |
|---------|---------|---------|
| API Name | `[PREFIX]_[Name]__c` | `PROJ_Invoice__c` |
| Filename | `[PREFIX]_[Name]__c.object-meta.xml` | `PROJ_Invoice__c.object-meta.xml` |
| Label | PascalCase, no prefix | `Invoice` |
| Plural Label | PascalCase, plural | `Invoices` |
| Validation Rule | Alphanumeric + `_`, NO `__c` | `Require_Status` |
| Field | `[Name]__c` (no prefix on fields) | `Status__c` |

## Troubleshooting

### Error: Sharing model conflict

**Error Message:**
```
Cannot set sharingModel to ReadWrite on a CustomObject with a MasterDetail relationship field
```

**Solution:**
1. Check if object has (or will have) Master-Detail field
2. Change sharing model to `ControlledByParent`
3. Redeploy

### Error: Reserved word in API name

**Error Message:**
```
The API name cannot use reserved words
```

**Solution:**
1. Check API name against reserved words list
2. Ensure prefix is included: `[PREFIX]_Name__c`
3. Choose different name if needed

### Error: Validation rule naming

**Error Message:**
```
The validation name can only contain alphanumeric characters...
```

**Solution:**
1. Remove `__c` suffix from validation rule name
2. Ensure name starts with letter
3. No consecutive underscores
4. Cannot end with underscore

### Error: Missing required fields

**Error Message:**
```
Required field missing: nameField
```

**Solution:**
1. Verify all required elements present:
   - `<label>`
   - `<pluralLabel>`
   - `<sharingModel>`
   - `<deploymentStatus>`
   - `<visibility>`
   - `<nameField>` with `<label>` and `<type>`
2. If AutoNumber, add `<displayFormat>` and `<startingNumber>`

### Error: Too many Master-Detail relationships

**Error Message:**
```
Cannot add more than 2 master-detail relationships
```

**Solution:**
1. Count existing Master-Detail fields
2. If already 2, use Lookup field instead
3. Consider restructuring data model

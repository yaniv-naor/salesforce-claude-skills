# SF Field Create

Creates Salesforce custom field metadata (`.field-meta.xml`) with proper configuration for all field types. **Works with any Salesforce project.**

## When to Use

- Creating custom fields on any object (standard or custom)
- Adding picklist fields with values
- Creating lookup or Master-Detail relationships
- Adding formula or rollup summary fields
- Setting up required fields and default values
- Configuring field-level security

## Instructions

### Step 1: Detect Project Prefix

Use `sf-prefix-detect` skill to determine if prefix is needed.

**Prefix rules for fields:**
- ✅ Fields on **standard objects** (Account, Contact, etc.) → **PREFIX REQUIRED**
  - Example: `PROJ_CustomField__c` on `Account`
- ❌ Fields on **custom objects** (ends with `__c`) → **NO PREFIX**
  - Example: `Status__c` on `PROJ_Invoice__c`
  - Reason: Object already has prefix, fields inherit namespace

### Step 2: Gather Field Information

Ask user for (or infer from request):

**Required:**
- **Parent object** - Which object gets this field? (e.g., `Account`, `PROJ_Invoice__c`)
- **Field name** (without prefix/suffix, PascalCase) - e.g., `Status`, `Priority`, `CustomField`
- **Field type** - See field types table below
- **Field label** - Human-readable name

**Optional (depends on field type):**
- **Description** - What is this field for?
- **Help text** - Inline help for users
- **Required** - Is this field mandatory?
- **Unique** - Enforce unique values?
- **External ID** - Use for integration?
- **Default value** - Pre-populate field
- **Picklist values** (for Picklist/Multipicklist)
- **Lookup target** (for Lookup/Master-Detail)
- **Formula** (for Formula fields)
- **Rollup summary** (for Master-Detail children)

**Auto-detected:**
- API Name: `[PREFIX?]_[FieldName]__c`
- File path based on object name

### Step 3: Determine Field Type

Choose appropriate field type:

| Field Type | Use For | Required Config |
|------------|---------|-----------------|
| **Text** | Short text (up to 255 chars) | Length |
| **Text Area** | Long text (up to 131,072 chars) | None |
| **Text Area (Long)** | Very long text, rich formatting | Visible lines |
| **Text Area (Rich)** | HTML formatted text | Visible lines |
| **Number** | Numeric values, calculations | Precision, scale |
| **Currency** | Money amounts | Precision, scale |
| **Percent** | Percentage values | Precision, scale |
| **Date** | Date only | None |
| **Date/Time** | Date and time | None |
| **Checkbox** | Boolean (true/false) | Default value |
| **Picklist** | Single-select dropdown | Picklist values |
| **Picklist (Multi-Select)** | Multi-select dropdown | Picklist values |
| **Email** | Email addresses | None |
| **Phone** | Phone numbers | None |
| **URL** | Web addresses | None |
| **Lookup** | Reference to another object | Related object |
| **Master-Detail** | Parent-child relationship | Related object |
| **Formula** | Calculated values | Formula, return type |
| **Rollup Summary** | Aggregate child records | Operation, child object |

### Step 4: Generate Field Metadata XML

Create `.field-meta.xml` file with proper structure:

**Basic structure:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<CustomField xmlns="http://soap.sforce.com/2006/04/metadata">
    <!-- Generated by Claude Code on [YYYY-MM-DD] -->
    
    <fullName>[PREFIX?]_[FieldName]__c</fullName>
    <label>[Field Label]</label>
    <description>[Description] - Generated by Claude Code</description>
    <type>[FieldType]</type>
    
    <!-- Type-specific configuration -->
    
    <!-- Common settings -->
    <required>false</required>
    <trackTrending>false</trackTrending>
    <unique>false</unique>
    <externalId>false</externalId>
</CustomField>
```

## Critical Rules & Constraints

### Prefix Rules (IMPORTANT!)

**Fields on Standard Objects → PREFIX REQUIRED:**
```
Account.PROJ_CustomField__c     ✅ Correct
Contact.PROJ_Email__c           ✅ Correct
Account.CustomField__c          ❌ Wrong - missing prefix
```

**Fields on Custom Objects → NO PREFIX:**
```
PROJ_Invoice__c.Status__c       ✅ Correct
PROJ_Invoice__c.Amount__c       ✅ Correct
PROJ_Invoice__c.PROJ_Status__c  ❌ Wrong - double prefix
```

### Master-Detail Constraints

**Maximum 2 per object:**
- First 2 relationships: Can be Master-Detail
- 3rd+ relationships: Must be Lookup

**Sharing model requirement:**
- Parent object MUST have `sharingModel` = `ControlledByParent`
- Deploy will fail if object has `ReadWrite` sharing

**Cascade behavior:**
- Deleting parent deletes all children (cannot be changed)
- Children automatically share security with parent
- Cannot reparent by default (use `reparentableMasterDetail` to enable)

### Rollup Summary Constraints

**Only available on Master-Detail parent:**
- Parent object can have rollup fields
- Child object cannot have rollup fields
- Requires Master-Detail relationship

**Operations:**
- COUNT, SUM, MIN, MAX
- Can filter child records with criteria

### Formula Field Constraints

**Cannot reference:**
- Long text areas
- Multi-select picklists (in some contexts)
- Encrypted fields

**Return type limits:**
- Text: 3,900 characters max
- Number/Currency: Standard precision/scale
- Date/DateTime: Standard format
- Checkbox: Boolean

**Formula size:**
- Maximum 3,900 characters
- Maximum 15 unique relationships per formula

### Unique & External ID

**Unique fields:**
- Text, Number, Email fields can be unique
- Case-sensitive or case-insensitive
- Existing records must have unique values

**External ID:**
- Automatically indexed for performance
- Used for upsert operations
- Improves query performance

## Troubleshooting

### Error: Master-Detail requires ControlledByParent

**Error:**
```
Cannot create Master-Detail field on object with ReadWrite sharing
```

**Solution:**
1. Update parent object metadata
2. Change `<sharingModel>` to `ControlledByParent`
3. Deploy object first
4. Then deploy Master-Detail field

### Error: Too many Master-Detail relationships

**Error:**
```
Cannot create more than 2 Master-Detail relationships
```

**Solution:**
1. Check existing Master-Detail fields on object
2. If already 2, use Lookup field instead
3. Consider data model redesign if needed

### Error: Unique constraint violation

**Error:**
```
Duplicate values found for unique field
```

**Solution:**
1. Query existing records for duplicates
2. Update records to have unique values
3. Then deploy field with unique constraint

### Error: Invalid formula syntax

**Error:**
```
Formula result is incompatible with formula return type
```

**Solution:**
1. Verify formula syntax in Formula Builder
2. Check return type matches field type
3. Test formula in Developer Console

### Error: Rollup on non-MD relationship

**Error:**
```
Summary fields can only be created on Master-Detail parent
```

**Solution:**
1. Verify relationship is Master-Detail (not Lookup)
2. Check field is on parent object (not child)
3. Ensure Master-Detail relationship exists

# SF Trigger Create

Creates complete trigger implementations with handler pattern. Generates trigger file, handler class, and comprehensive test class following Salesforce best practices. **Works with any Salesforce project.**

## When to Use

- Creating new triggers for any Salesforce object
- Adding trigger contexts to existing triggers
- Implementing handler pattern for triggers
- Setting up trigger testing framework

## Instructions

### Step 1: Detect Project Prefix

Use `sf-prefix-detect` skill to determine the project prefix.

**Quick fallback:**
1. Get working directory name
2. Transform: `Crm[Name]` → `[NAME]_` or `[Name]` → `[NAME]_`
3. Validate: uppercase + underscore

### Step 2: Gather Information

Ask user for (or infer from request):

**Required:**
- **Object API name** (e.g., `CustomObject__c`, `Account`, `Contact`)
- **Trigger contexts** needed:
  - before insert
  - before update
  - before delete
  - after insert
  - after update
  - after delete
  - after undelete
- **Purpose**: Brief description of what the trigger does

**Auto-detected:**
- Trigger name: `[PREFIX]_[ObjectName]Trigger`
- Handler name: `[PREFIX]_[ObjectName]Handler`
- Test name: `[PREFIX]_[ObjectName]Handler_Test`
- Object name extraction from API name (e.g., `ABC_Document__c` → `Document`)

**Smart defaults:**
- If user doesn't specify contexts, include all 7 contexts (can be commented out)
- API version: Read from `sfdx-project.json` or default to `66.0`

### Step 3: Generate Trigger File

Create minimal trigger that delegates all logic to handler:

```apex
/*
CREATED BY: Claude Code
CREATED DATE: [Month, Year]
DESCRIPTION: Trigger for [ObjectName] - [Purpose Description]
*/
// Generated by Claude Code on [YYYY-MM-DD]
trigger [PREFIX]_[ObjectName]Trigger on [ObjectAPIName] (
    before insert, before update, before delete,
    after insert, after update, after delete, after undelete
) {
    [PREFIX]_[ObjectName]Handler handler = new [PREFIX]_[ObjectName]Handler();

    if (Trigger.isBefore) {
        if (Trigger.isInsert) {
            handler.beforeInsert(Trigger.new);
        } else if (Trigger.isUpdate) {
            handler.beforeUpdate(Trigger.newMap, Trigger.oldMap);
        } else if (Trigger.isDelete) {
            handler.beforeDelete(Trigger.oldMap);
        }
    }

    if (Trigger.isAfter) {
        if (Trigger.isInsert) {
            handler.afterInsert(Trigger.newMap);
        } else if (Trigger.isUpdate) {
            handler.afterUpdate(Trigger.newMap, Trigger.oldMap);
        } else if (Trigger.isDelete) {
            handler.afterDelete(Trigger.oldMap);
        } else if (Trigger.isUndelete) {
            handler.afterUndelete(Trigger.newMap);
        }
    }
}
```

**Trigger principles:**
- ✅ Minimal code in trigger (only routing logic)
- ✅ All business logic in handler
- ✅ One trigger per object
- ✅ All contexts declared upfront (easier to add logic later)

## Trigger Best Practices

### One Trigger Per Object Rule

**Why it matters:**
- Multiple triggers on same object = unpredictable execution order
- Governor limits shared across all triggers
- Debugging becomes nightmare
- Maintenance overhead increases

**Solution: Handler Pattern**
- ✅ One trigger delegates to one handler
- ✅ Handler organizes logic by context
- ✅ Helper methods keep code clean
- ✅ Easy to test and maintain

### Bulkification Requirements

**Always design for bulk:**
- ✅ Accept collections, not single records
- ✅ SOQL queries outside loops
- ✅ DML statements outside loops
- ✅ Use Maps for efficient lookups
- ✅ Test with 200+ records

**Bad example (NOT bulkified):**
```apex
// ❌ WRONG - SOQL in loop
for ([Object] record : newRecords) {
    List<Related__c> related = [SELECT Id FROM Related__c WHERE Parent__c = :record.Id];
}
```

**Good example (bulkified):**
```apex
// ✅ CORRECT - SOQL outside loop
Set<Id> parentIds = new Set<Id>();
for ([Object] record : newRecords) {
    parentIds.add(record.Id);
}
List<Related__c> allRelated = [
    SELECT Id, Parent__c FROM Related__c
    WHERE Parent__c IN :parentIds
];
Map<Id, List<Related__c>> relatedByParent = new Map<Id, List<Related__c>>();
for (Related__c rel : allRelated) {
    if (!relatedByParent.containsKey(rel.Parent__c)) {
        relatedByParent.put(rel.Parent__c, new List<Related__c>());
    }
    relatedByParent.get(rel.Parent__c).add(rel);
}
```

### Trigger Context Guidelines

**Before Triggers (before insert/update/delete):**
- ✅ Use for: Field validation, default values, derived fields
- ✅ Access: `Trigger.new` (before insert = List, before update/delete = also available as Map)
- ❌ Cannot: Perform DML on same object type
- ❌ Cannot: Query records being processed

**After Triggers (after insert/update/delete/undelete):**
- ✅ Use for: Creating related records, callouts, complex updates
- ✅ Access: `Trigger.newMap`, `Trigger.oldMap` (always Maps with Ids)
- ✅ Can: Query and update related objects
- ✅ Can: Perform DML on different objects

### Recursion Prevention

When trigger logic updates same object, prevent infinite loops:

```apex
public class [PREFIX]_Handler {
    private static Boolean isExecuting = false;

    public void afterUpdate(Map<Id, [Object]> newMap, Map<Id, [Object]> oldMap) {
        // Prevent recursive execution
        if (isExecuting) {
            return;
        }
        isExecuting = true;

        try {
            // Your logic that might update same object
            
        } finally {
            isExecuting = false; // Always reset in finally block
        }
    }
}
```

**Alternative pattern (field-based check):**
```apex
public void afterUpdate(Map<Id, [Object]> newMap, Map<Id, [Object]> oldMap) {
    Set<Id> changedRecordIds = new Set<Id>();
    
    for (Id recordId : newMap.keySet()) {
        [Object] newRec = newMap.get(recordId);
        [Object] oldRec = oldMap.get(recordId);
        
        // Only process if specific field changed (prevents recursion)
        if (newRec.Status__c != oldRec.Status__c) {
            changedRecordIds.add(recordId);
        }
    }
    
    // Only execute if there are actual changes
    if (!changedRecordIds.isEmpty()) {
        // Process changes
    }
}
```

## Troubleshooting

### Issue: Trigger already exists

**Solution:**
1. Check existing trigger: `find . -name "*Trigger.trigger" -type f`
2. Ask user:
   - Add logic to existing trigger/handler?
   - Create separate handler?
   - Overwrite existing (show content first)?

### Issue: Recursive trigger loop

**Symptoms:** CPU timeout, governor limits exceeded

**Solution:**
1. Add recursion prevention (static boolean or field-based check)
2. Verify trigger only updates when field actually changed
3. Test with bulk operations to catch recursion

### Issue: Test class fails

**Common causes:**
- Missing required fields in test data
- Validation rules not satisfied
- Insufficient permissions in test context

**Solution:**
1. Read object metadata for required fields
2. Use `System.runAs()` for permission tests
3. Check validation rules and ensure test data passes

### Issue: Coverage below 75%

**Solution:**
1. Add test methods for untested contexts
2. Add bulk tests (200+ records)
3. Test positive and negative scenarios
4. Add error handling tests
5. Test helper methods individually

### Common Patterns

**Pattern 1: Set default values (Before Insert)**
```apex
public void beforeInsert(List<[Object]> newRecords) {
    for ([Object] record : newRecords) {
        if (String.isBlank(record.Status__c)) {
            record.Status__c = 'New';
        }
    }
}
```

**Pattern 2: Prevent invalid changes (Before Update)**
```apex
public void beforeUpdate(Map<Id, [Object]> newMap, Map<Id, [Object]> oldMap) {
    for (Id recordId : newMap.keySet()) {
        [Object] newRec = newMap.get(recordId);
        [Object] oldRec = oldMap.get(recordId);
        
        if (newRec.Status__c == 'Closed' && oldRec.Status__c != 'Closed') {
            if (newRec.RequiredField__c == null) {
                newRec.addError('Cannot close without required field');
            }
        }
    }
}
```

**Pattern 3: Create related records (After Insert)**
```apex
public void afterInsert(Map<Id, [Object]> newMap) {
    List<RelatedObject__c> relatedRecords = new List<RelatedObject__c>();
    
    for ([Object] record : newMap.values()) {
        relatedRecords.add(new RelatedObject__c(
            ParentId__c = record.Id,
            Name = record.Name + ' Related'
        ));
    }
    
    if (!relatedRecords.isEmpty()) {
        insert relatedRecords;
    }
}
```

**Pattern 4: Update related records (After Update)**
```apex
public void afterUpdate(Map<Id, [Object]> newMap, Map<Id, [Object]> oldMap) {
    Set<Id> changedRecordIds = new Set<Id>();
    
    for (Id recordId : newMap.keySet()) {
        if (newMap.get(recordId).Status__c != oldMap.get(recordId).Status__c) {
            changedRecordIds.add(recordId);
        }
    }
    
    if (!changedRecordIds.isEmpty()) {
        List<RelatedObject__c> relatedToUpdate = [
            SELECT Id, Status__c, ParentId__c
            FROM RelatedObject__c
            WHERE ParentId__c IN :changedRecordIds
        ];
        
        for (RelatedObject__c related : relatedToUpdate) {
            related.Status__c = newMap.get(related.ParentId__c).Status__c;
        }
        
        update relatedToUpdate;
    }
}
```
